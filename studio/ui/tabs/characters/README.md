# Characters tab

Everything the tab owns is in this directory (`index.mjs` and its modules, `server.mjs`, `sheet.mjs`, `characters.css`, `i18n/`, tests). It follows the tab contract in [`../../README.md`](../../README.md) and touches no shared file; the only project data it reads is the pack.

## What it shows

| Area | Content |
|---|---|
| Roster (left) | Players, mobs, bosses, NPCs and pets of the core manifest and the Longtime design manifest, by readiness (packed / authored / planned). Planned characters have no frames; they keep their brief, clip plan and facings. Filters (category, readiness, text) live in the URL. |
| Stage (centre) | Four-facing turnaround of the selected clip and frame; clip tabs and a frame strip with per-frame durations; play/pause with speed (`Space`, and `←` `→` step frames); onion skin (previous gold, next jade); overlays for pivot, foot point and hitbox; raw ↔ processed comparison (processed, raw, a draggable wipe, diff of changed pixels only); the shared pixel viewer (`../../pixelview.mjs`): integer zoom 1/2/3/4/6/8/12/16× or auto, pixel grid from 8× (`G`), three checker backgrounds, pointer pixel coordinates, keys `Space` `←` `→` `+` `-` `G`. Characters with a forge bake can switch between the library frames and the bake. |
| Frame (right) | File, editor key, publish note, pivot editor (type or click the selected facing, then save as a new revision), revision status and history, and the comments. |
| Cross-facing (right) | The four facings of the current frame, rig landmark boxes, west against mirrored east (a difference map and a verdict that says whether east is a mirror copy), and for rigged characters a per-facing check that each asymmetric mark sits in its box. |
| Card (right) | Names, brief, palette roles with hex, provenance, rig summary, motion templates per clip and the forge experiment files. Read only. |
| Export (right) | Contact sheet PNG (every clip, one row per facing, integer scale), generated by the server and deterministic. Sheets are limited to 16 megapixels (`maxSheetPixels` in `layout.mjs`): the server answers 422 `sheet_too_large` with the largest allowed scale, before decoding or allocating anything large, and the panel offers only scales that fit (the biggest boss tops out at 3× for all clips; one clip allows more). |

## What it does not do, and why

- **Hitbox**: the project defines no hitbox for any character. The overlay draws the manifest hitbox when there is one, otherwise the sprite bounds, dashed and labelled. It cannot be edited because the editor API stores only `pivot` (and `durationMs` for VFX).
- **Foot point**: read only, from the character's `anchor.json` (core) or profile pivot (Longtime). Pivot is the editable per-frame metadata.
- **Durations**: Longtime clips come from the design manifest (one time per clip); core clips have none, so playback uses `defaultFrameMs` from the pack and says so with an asterisk. There is no duration editing.
- **Pixels** are not edited here; the Asset Inspector's frame editor does that (same keys, same revisions).
- **Publishing** frames into atlases is not offered: character frames cannot be promoted yet (see `studio/server/README.md`), and the Frame tab says so.
- **Rig and card** exist only where files exist. Today the only rig is the bake-off marten (prototype format, `assets/experiments/forge_bakeoff/`); a `studio.rig` file is read the same way. The "card" is assembled from the manifest, provenance files, rig and motion library; there is no separate card file yet.
- Approving is a human action in this UI; nothing here is exposed to an agent.

## Pack configuration (`ui.tabs.characters` in `studio.project.json`)

| Key | Meaning |
|---|---|
| `categories` | catalog categories that count as characters, in roster order |
| `facings` | facing order of the turnaround |
| `defaultFrameMs` | preview frame time for clips without one |
| `rawRoots` | directories searched (depth ≤ 2) for `<id>/<clip>/<facing>/frame_NNN.png` raw frames |
| `rigs` | rig file path templates (`{id}`); `studio.rig` and the bake-off prototype format are read |
| `experiments` | forge experiment directories (`{id}`): turnaround, comparison sheets, prompt, `frames/` |
| `bodyPlans` | profile → body plan, used to find motion templates when the rig does not say |

Colours, labels and the project name come from the shell (the pack's `ui` section); the tab has no project literals of its own beyond these keys.

## URL

`#/characters/<id>?clip=&dir=&frame=` plus: `panel=frame|facing|card|export`, `compare=processed|raw|split|diff`, `src=bake`, `onion=1`, `ov=pivot,foot,hitbox`, `zoom=1..16`, `source=<catalog source>` (only for an id in two sources), and the roster filters `cat=`, `ready=`, `q=`. A selection that does not exist is corrected to the first clip, facing and frame the character has.

## Server (`/api/tabs/characters/…`)

`roster`, `asset?id=&source=` and `sheet.png?id=&scale=1..8&clip=`; read only, loopback and same origin. Frames themselves are served by the static server from `/assets/…`; saving and review use `/api/editor/…`.

## Tests

`node --test 'studio/ui/tabs/characters/*.test.mjs'` (route state, roster filter, selection, durations, playback, cross-facing maths, server and contact sheet). `characters-browser.mjs` (not named `*.test.mjs`, so the command above skips it) is a Playwright script (needs `playwright-core` and Chromium; not part of the baseline).

## Layout and shared components (wave 3B)

The tab's root carries `ui-kit`, so its buttons (`.btn`), segmented controls (`.seg`: raw/processed, frame source, panel tabs), chips (`.chip`: filters, clips, readiness and review status), fields (`.field`), empty and loading states (`.empty`, `.skeleton`) and notices (`.toast`) are the shared components from `studio/ui/components.css`; `characters.css` only lays them out. Status labels come from `badge(kind, value, label)` in `dom.mjs` (class `chip ok|warn|danger readiness-… | status-…`).

Below 900 px the roster and the detail are one column shown one at a time: `.characters[data-view="list"|"detail"]` follows whether a character is selected, and a back button (`.back-bar`) in the detail view returns to the roster (a normal history entry, so the browser's Back does the same). The category chips and the readiness filter collapse behind a "Filters" button. Names and ids are cut with an ellipsis and carry a `title` tooltip. The roster and the detail each show a skeleton while loading; a failed request shows an error state with a retry button.

The decision bar is `section.decide[data-slot="decision"]`, sticky under the stage (`decide.mjs`): Approve, Request changes and Comment for the frame on show, on the existing human review route (`/api/editor/review`, revision-checked, human only; there is no other approval path). The seal (`seal.mjs`) plays only after the server confirmed an approval and only if the "seal effect" setting is on and the system does not ask for reduced motion. Selecting a character and pressing Approve is two actions. The bar keeps the note and the keyboard focus across redraws and is hidden while the frame has no editor key.

Motion: pointing at or focusing a roster row loops that character's idle on its thumbnail (`preview.mjs`, frames fetched once and cached; a still thumbnail under reduced motion). The clip tabs on the stage (`role=tablist`, arrow keys) play the chosen clip at once; choosing the clip on show toggles playback. Playback reuses the stage's loop, so the URL still records the frame it stops on.
